# Full-repo inconsistency audit — findings for review (2026-09-28)

Branch: `exp/rlcd-laya-finetune` @ `e523119`. Scope: src/, scripts/, tests/,
docs + runs artifacts. Method: parallel static audit (4 agents) + independent
spot-verification of every P0/P1 by the lead. One sub-agent false positive was
caught and corrected during lead verification (see F9 note).

Each finding below lists its evidence locations. Verify each against the repo
and answer CONFIRMED / PARTIAL / REFUTED.

## P0 — crashes at runtime

### F1. `exp_rlcd_loo_transfer.py` NameError on `torch`
- `scripts/exp_rlcd_loo_transfer.py:42-44` — `_eval_arm` references
  `torch.cuda.is_available()` at module scope, but the only `import torch` is
  local to `_run_fold` (line 116). Introduced by cleanup commit `e523119`
  (old `_eval_arm` had its own local import).
- Effect: the LOO-transfer experiment is not re-runnable as-is.
- Proposed fix: add `import torch` inside `_eval_arm` (or module top).

## P1 — affects experiment numbers/conclusions

### F2. `RLCDConfig.margin` never reaches `mine_pairs`; sweep margin axis is a no-op
- `src/opt_agent/system1/rlcd.py:292` defines `margin`; `mine_pairs` accepts
  it (`rlcd.py:80-86`); but `build_item` (`rlcd.py:176-179`) and
  `train_rlcd._build` (`rlcd.py:447`) call `mine_pairs(record)` without it;
  `config.margin` is only echoed into the report (`rlcd.py:551`).
- `scripts/sweep_rlcd.py` grid includes margin 0.0 vs 0.05 arms → those arms
  are computationally identical; the ~0.5 pp differences in
  `runs/exp_rlcd_sweep.json` (e.g. bt_beta1_margin0 0.8789 vs margin0.05
  0.8737) are GPU nondeterminism, not a margin effect.
- Proposed fix: thread `config.margin` through `build_item` → `mine_pairs`
  (and `evaluate_ranking` for consistency), or delete the config field and
  the sweep axis.

### F3. Cleanup commit changed `analyze_rlcd_ci.py` metric semantics; two artifacts now disagree
- Pre-`e523119` local implementation: gold top-1 against `gold_probs`, NaN
  sentinel, no ≥2-valid-gold requirement. Post-consolidation
  `_rlcd_common.per_record_laya`: raw-utility top-1, `None` sentinel, ≥2
  valid gold utilities required.
- `runs/exp_rlcd_ci.json` (regenerated by `e523119`) top1.bt 0.3739 /
  top1.proper 0.2609 vs paper-facing `runs/EXP_RLCD_REPORT.md:16-17` and
  `PROGRESS_BRANCH.md:86` quoting bt 0.383 / proper 0.252 (from
  `exp_rlcd_report.json`). Commit message claims "reproduces ... exactly" —
  true only for pairwise accuracy.
- Latent crash: `scripts/analyze_rlcd_ci.py:103` — `if v[3] == v[3]` is a NaN
  filter, but the new sentinel is `None`; `None == None` is True → `sum()`
  raises TypeError once any record yields `log_score=None`.
- Proposed fix: decide the canonical estimand; either restore old semantics
  or update paper-facing docs to the regenerated numbers; fix the filter to
  `is not None and v[3] == v[3]`.

### F4. `error_guided_sampling` with n_samples>1 evaluates the same point n times
- `src/opt_agent/actions/executor.py:200-202` — perturbation `delta` drawn
  once, then `candidates.repeat(n_samples, 1)` duplicates the identical row;
  comment claims "repeat with different perturbations". Factory
  (`src/opt_agent/actions/factory.py:94`) samples `n_samples` in [1,3].
- Effect: budget is charged n times for n duplicate evaluations; claimed
  diversity does not exist.
- Proposed fix: draw n independent perturbations (loop or batched rand with
  n rows), or clamp n_samples to 1 for this action.

### F5. Partial-rollout datasets violate the documented record-schema invariant
- `src/opt_agent/dataset/decision_record.py:32-34` — invariant: keys of
  candidate_actions / gold_probs / rollout_results identical, "enforced by
  the generator".
- `src/opt_agent/dataset/analysis.py:37` — `analyze_dataset` raises
  ValueError on set mismatch ("unaligned action vocabulary").
- `src/opt_agent/dataset/generator.py:422-437` — with
  `rollout_action_subsample=k<8`, `candidate_actions` keeps all 8 while
  `gold_probs`/`rollout_results` cover only k ids (metadata note admits it).
- Effect: `validate_record`/`analyze_dataset` reject the shipped longhorizon
  (k=4) datasets; the documented invariant is false for a supported mode.
- Proposed fix: relax the invariant to "gold_probs ⊆ candidate_actions" (and
  update the docstring + analysis check), or emit candidate_actions as the
  rolled subset.

### F6. `analyze_rlcd_ci.paired_bootstrap` uses arm A's pair total as denominator for both arms
- `scripts/analyze_rlcd_ci.py:38-61` — `tot_pairs = sum(per_rec_a[i][1])`,
  then `ca/tot - cb/tot`. RF pair sets (from `rf_pairwise_and_top1` over
  `extract_utilities`-rescaled gold) need not match Laya pair totals.
- Contrast: `_rlcd_common.paired_accuracy_diffs` does the correct per-record
  `ca/ta − cb/tb` and is used by `exp_rlcd_loo_confirmatory.py`.
- Proposed fix: switch `analyze_rlcd_ci` to `paired_accuracy_diffs`.
